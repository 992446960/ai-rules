## 缓存视图侦听全局泛名 `params.id` 导致跨路由串用主键

**类别**：`边界/路由`  
**语言/生态**：`通用 · SPA（Vue Router、React Router 等）`

### 触发条件

> 使用 **KeepAlive（或等价缓存）** 时，从页面 A 切到 **URL 动态段同名**（如均为 `:id`）但 **语义不同** 的页面 B，出现 **A 侧仍用当前 URL 的 `id` 发请求**，表现为串 id、误调接口。

### 根因

当前激活路由只有一份；**`useRoute()` 始终反映激活匹配**。被缓存的 A 仍存活时，若 **`watch(params.id)`** 等仍运行，切到 B 后 **同名键已是 B 的主键**，逻辑却仍按 A 解释。

### 规避方法

- 缓存页避免把 **`params.id` 等泛名**当作唯一侦听源；路径改为 **`:sessionId` / `:fileId`** 等语义化段名。
- 读参或触发副作用前校验 **`route.name` / `matched`** 仍属本业务，否则不传 id、不请求。
- 用 **props、meta、store 显式字段** 承载业务主键，与全站其它 `:id` 解耦。

### 举例

> 曾见于：嵌套路由下「会话与文件预览」均用 `:id`；预览激活后，缓存中的会话树仍监听全局 `id` 并误拉消息接口。

## 挂载与侦听双入口重复拉取同一资源

**类别**：`异步/时序`  
**语言/生态**：`通用 · 前端组件`

### 触发条件

> 同一数据在 **`onMounted`（或 `useEffect([])`）** 与 **`watch` / 依赖型 `useEffect`** 中各拉一次；**props 异步就绪或二次赋值** 时出现 **重复请求**。

### 根因

存在 **两条独立副作用入口**，未由 **单一依赖列表** 统一驱动，首屏与更新路径各触发一次 `load`。

### 规避方法

- 合并为 **`watch(deps, load, { immediate: true })`** 或 **单一 effect 依赖全集**，去掉 mount 内并行重复拉取。
- 评审依赖是否覆盖所有应触发刷新的输入。

### 举例

> 曾见于：预览组件中 `loadFile` / `loadCards` 在 mount 与 watch 各走一遍。
