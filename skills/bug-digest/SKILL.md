# Bug Digest Skill

## 目标

将具体 bug 抽象为**可迁移的通用经验**，与项目、语言版本、框架解耦。  
项目仅作例证，核心是"触发条件 → 根因 → 规避方法"三元组。

---

## 工作流

### 1. 信息提取

从用户描述中提取：

| 字段 | 含义 |
|------|------|
| 现象 | 错误表现（报错文本、异常行为） |
| 触发条件 | 什么操作/场景引发 |
| 根因 | 本质原因（类型错误、时序问题、边界遗漏……） |
| 修复方式 | 如何解决 |
| 举例来源 | 项目/语言（仅作脚注，不影响正文） |

若信息不足，**精准追问一条**，不多问。

---

### 2. 文件命名

生成文档时，文件名须**概述 bug 本质**，格式：

```
[类别]-[核心问题简述].md
```

命名规则：
- 用连字符，全小写，英文或拼音均可
- 类别前缀取自归档分类（async / type / boundary / config / dom / api）
- 核心问题简述 2~4 词，直指根因

示例：
- `async-setup-lifecycle-hook-missing.md`
- `type-null-not-checked-before-access.md`
- `config-env-var-undefined-in-prod.md`

---

### 3. 生成条目格式

每条经验输出如下 Markdown 块：

```markdown
## [简洁标题，描述本质问题]

**类别**：`[类型/异步/边界/配置/环境/…]`  
**语言/生态**：`[JS / Python / 通用 / …]`

### 触发条件
> 在 [场景] 时，[做了什么]，出现 [现象]。

### 根因
[1-3 句，说清楚为什么会这样，技术层面]

### 规避方法
- [具体可操作的检查点或编码习惯]
- [可选：相关 lint 规则 / 类型注解 / 断言]

### 举例
> 曾见于：[项目类型或场景简述，不含项目名]
```

---

### 4. 归档建议

若用户已积累多条，提示可按**类别**整理为一份 `bug-notes.md`，便于检索。  
分类参考：

- `异步/时序`
- `类型/转换`
- `边界/空值`
- `配置/环境`
- `DOM/渲染`
- `API/协议`

---

## 原则

1. **去项目化**：修复过程细节留在举例脚注，正文只写可迁移结论。
2. **精简**：每条不超过 200 字，宁缺毋滥。
3. **可操作**：规避方法必须是下次写代码时能执行的动作，不写废话。
4. **不重复**：若当前 bug 与已有条目高度重合，提示用户补充差异即可，不新建。
