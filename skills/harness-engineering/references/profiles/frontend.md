# Frontend Profile

Use this profile when the repository primarily delivers browser UI, web apps, or design-heavy flows.

## Biases

- Include `ui-verify` as a first-class workflow.
- Prefer explicit build, lint, typecheck, and screenshot verification commands.
- Observability should mention browser console, network failures, and UI smoke paths.

## Expected Repo Outputs

- `docs/architecture.md` should explain page and component boundaries.
- `CLAUDE.md` should list dev server, build, test, lint, and UI verification commands.
- `observability/README.md` should mention screenshots, DOM snapshots, and runtime console checks.
